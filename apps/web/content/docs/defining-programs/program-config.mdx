The program config is the top-level object that combines your accounts, instructions, errors, and events into a single program definition. It is also the object you pass to the client SDK.

## The full shape

```typescript
import { bs, cpi } from "better-sol/program"

const Counter = bs.account({
  count: bs.u64(),
  authority: bs.pubkey(),
  isActive: bs.bool(),
}).derive(seed => ["counter", seed.authority])

export const counter = bs.program({
  name: "counter",
  address: "91eZUq6pokUtTcucXV1BVCAaarMy7EiHWv3SogYNZ7xs",
  accounts: { Counter },
  errors: {
    Unauthorized: "Only the authority can perform this action",
    NotActive: "Counter is not active",
  },
  events: {
    Incremented: { newCount: bs.u64(), authority: bs.pubkey() },
  },
}, ix => ({
  initialize: ix({
    accounts: {
      counter: bs.init(Counter),
      authority: bs.signer(),
    },
    args: { initialValue: bs.u64() },
    run: ({ counter, authority }, { initialValue }) => {
      counter.count = initialValue
      counter.authority = authority
      counter.isActive = true
    },
  }),

  increment: ix({
    accounts: {
      counter: bs.mut(Counter),
      authority: bs.signer(),
    },
    args: { amount: bs.u64() },
    run: ({ counter, authority }, { amount }, ctx) => {
      ctx.require(authority === counter.authority, "Unauthorized")
      counter.count += amount
      ctx.emit("Incremented", { newCount: counter.count, authority })
    },
  }),
}))
```

## Config fields

| Field | Type | Required | Description |
|---|---|---|---|
| `name` | `string` | Yes | The program name. Used as the Rust module name and in the generated IDL. Must be a valid Rust identifier (lowercase, underscores). |
| `address` | `string` | Yes | The on-chain program ID (base58 address). Generated by the CLI when you run `create`. |
| `accounts` | `Record<string, AccountDefinition>` | No | Account definitions registered for the typed client. Without this, `derive()` and `fetch()` will not be available. |
| `errors` | `Record<string, string>` | No | Custom error definitions. Keys are error names (used in `ctx.require()`), values are human-readable messages. |
| `events` | `Record<string, FieldSchema>` | No | Event definitions. Keys are event names (used in `ctx.emit()`), values are field schemas defining the payload. |

## The ix callback

The second argument to `bs.program()` is a function that receives `ix` and returns an object of instruction definitions:

```typescript
bs.program({ ... }, ix => ({
  instructionA: ix({ ... }),
  instructionB: ix({ ... }),
  instructionC: ix({ ... }),
}))
```

Each key becomes a method on the client. You call it as `sol.counter.instructionA(...)`. The key also becomes the Anchor instruction name in the generated Rust, converted to snake_case. So `incrementCount` becomes `increment_count` in Rust.

## Program address

The `address` field is the permanent on-chain identity of your program. It is generated when you run `create`:

```bash
npx @better-sol/cli create counter
# → Program:  91eZUq6pokUtTcucXV1BVCAaarMy7EiHWv3SogYNZ7xs
# → Keypair:  .better-sol/counter.json
```

The keypair file at `.better-sol/counter.json` contains the private key for this address. The CLI uses it for deployment. Never commit it to git.

## Multiple programs in one project

You can define multiple programs and register them all with the same client:

```typescript
// programs/counter.ts
export const counter = bs.program({ name: "counter", ... }, ix => ({ ... }))

// programs/marketplace.ts
export const marketplace = bs.program({ name: "marketplace", ... }, ix => ({ ... }))
```

```typescript
// client.ts
import { betterSol, keypairFile } from "better-sol"
import { counter } from "./programs/counter"
import { marketplace } from "./programs/marketplace"

const sol = await betterSol({
  cluster: "devnet",
  payer: keypairFile("./keypair.json"),
  programs: { counter, marketplace },
})

// Both programs are available
await sol.counter.increment({ ... })
await sol.marketplace.list({ ... })
```

The CLI discovers all programs in the `programs/` directory (configurable with `--src`). Each program gets its own section on the client.

## Type inference

The program definition is the single source of truth. TypeScript infers everything from it:

```typescript
// Instruction parameter types are inferred
type IncrementParams = bs.InferArgs<typeof counter.instructions.increment>
// → { counter: string; authority?: string; amount: bigint }
// (authority is optional because bs.signer() auto-fills)

// Account data types are inferred
type CounterData = bs.InferFields<typeof Counter.fields>
// → { count: bigint; authority: string; isActive: boolean }

// Instruction names are inferred
type IxNames = keyof typeof counter.instructions
// → "initialize" | "increment" | "close"

// Error names are inferred and type-checked
ctx.require(condition, "Unauthorized")  // valid
ctx.require(condition, "FooError")       // TypeScript error
```
