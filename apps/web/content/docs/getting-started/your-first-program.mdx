title: Your First Program
description: Build, deploy, and interact with a counter program on devnet.

In this guide you will create a counter program, deploy it to Solana devnet, and interact with it using the typed client. The whole thing takes about five minutes.

## Step 1: Create a new program

The CLI scaffolds a program with a basic counter template:

```bash
npx @better-sol/cli create counter
```

This generates two things:

- `programs/counter.ts` — your program definition (TypeScript)
- `.better-sol/counter.json` — the program keypair (used for deployment)

<Callout>
The keypair contains the private key for your program address. **Do not commit it to git.** Add `.better-sol/` to your `.gitignore`.
</Callout>

## Step 2: Look at the program

Open `programs/counter.ts`. The template looks like this:

```typescript
import { bs, cpi } from "better-sol/program"

const Counter = bs.account({
  count: bs.u64(),
  authority: bs.pubkey(),
  isActive: bs.bool(),
}).derive((seed) => ["counter", seed.authority])

export const counter = bs.program(
  {
    name: "counter",
    address: "<generated-address>",
    accounts: { Counter },
    errors: {
      Unauthorized: "Only the authority can update this counter",
      NotActive: "Counter is not active",
    },
  },
  ix => ({
    initialize: ix({
      accounts: {
        counter: bs.init(Counter),
        authority: bs.signer(),
      },
      args: { initialValue: bs.u64() },
      run: ({ counter, authority }, { initialValue }) => {
        counter.count = initialValue
        counter.authority = authority
        counter.isActive = true
      },
    }),

    increment: ix({
      accounts: {
        counter: bs.mut(Counter),
        authority: bs.signer(),
      },
      args: { amount: bs.u64() },
      run: ({ counter, authority }, { amount }, ctx) => {
        ctx.require(authority === counter.authority, "Unauthorized")
        ctx.require(counter.isActive, "NotActive")
        counter.count += amount
      },
    }),
  })
)
```

Do not worry about understanding every line right now. The important parts:

- **`bs.account({ ... })`** defines the on-chain data layout
- **`.derive()`** specifies PDA seeds so the address is deterministic
- **`bs.program({ ... }, ix => ({ ... }))`** wraps everything into a program with instructions
- **`ix({ ... })`** defines an instruction with accounts, arguments, and the `run()` body
- **`ctx.require()`** checks conditions and throws custom errors

Each of these is covered in detail in the [Defining Programs](/docs/defining-programs/types) section.

## Step 3: Deploy to devnet

You need a keypair to pay for the deployment. If you do not have one, the Solana CLI (installed automatically by the deploy command) can create one:

```bash
solana-keygen new --no-bip39-passphrase -o ./keypair.json
```

Then fund it with some devnet SOL:

```bash
solana airdrop 2 ./keypair.json --url devnet
```

Now deploy:

```bash
npx @better-sol/cli deploy
```

The CLI does three things:

1. Parses your TypeScript program definition
2. Transpiles it to Anchor Rust and compiles it to sBPF bytecode on the cloud compiler
3. Deploys the compiled `.so` binary to Solana using the program keypair

<Callout type="info">
First time deploying? The CLI installs the Solana CLI automatically. This takes about a minute. After that, deploys are fast.
</Callout>

## Step 4: Use the typed client

Create a file called `client.ts` (or add this to any script):

```typescript
import { betterSol, keypairFile } from "better-sol"
import { counter } from "./programs/counter"

const sol = await betterSol({
  cluster: "devnet",
  payer: keypairFile("./keypair.json"),
  programs: { counter },
})

// Derive the counter PDA from your wallet address
const counterAddr = await sol.counter.accounts.Counter.derive({
  authority: sol.payer,
})

// Initialize the counter with a starting value
await sol.counter.initialize({
  counter: counterAddr,
  initialValue: 0n,
})

// Increment by 5
await sol.counter.increment({
  counter: counterAddr,
  amount: 5n,
})

// Read the data back
const data = await sol.counter.accounts.Counter.fetch(counterAddr)
console.log("count:", data?.count)         // 5n
console.log("authority:", data?.authority) // your address
console.log("active:", data?.isActive)     // true
```

Run it:

```bash
npx tsx client.ts
```

Notice a few things:

- **No code generation step.** The same `counter` object you defined in `programs/counter.ts` is passed directly to `betterSol()`. The client methods are inferred from it at runtime.
- **Accounts are typed.** `sol.counter.accounts.Counter.fetch()` returns `{ count: bigint; authority: string; isActive: boolean }` or `null`. You never write these types yourself.
- **The signer auto-fills.** The `authority` account is declared as `bs.signer()` in the program definition, so it is optional in the call. When you omit it, the client uses `sol.payer`.
- **PDAs are derived from your definition.** The seeds you specified in `.derive()` determine what inputs `derive()` expects. Here it needs an `authority` address.

## Step 5: Close the counter

When you are done, you can close the account to reclaim the rent:

```typescript
await sol.counter.close({
  counter: counterAddr,
})
```

## What just happened

You wrote one TypeScript file that served three purposes:

1. **The program definition** that the transpiler converted to Anchor Rust and compiled to on-chain bytecode
2. **The typed client** that `betterSol()` used to generate instruction methods with full type inference
3. **The source of truth** for everything: account layouts, PDA seeds, instruction parameters, error names

No separate IDL file. No Rust toolchain. No code generation step.
