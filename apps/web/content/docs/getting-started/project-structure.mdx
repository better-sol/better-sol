When you run `npx @better-sol/cli create counter`, the CLI sets up a small, predictable project structure. Here is what each piece does.

### `programs/counter.ts`

Your program definition. This is the single source of truth. It defines accounts, instructions, errors, events, and PDA seeds. The transpiler reads this file to generate Rust. The client SDK reads the same object at runtime to build typed instruction methods.

You can have multiple program files in this directory. The CLI discovers all of them when you run `deploy`.

### `.better-sol/counter.json`

The program keypair. This is the public/private key pair that identifies your program on-chain. The CLI generates it when you run `create` and uses it when you run `deploy`.

<Callout type="warn">
This file contains a private key. **Never commit it to version control.** Add `.better-sol/` to your `.gitignore`.
</Callout>

### `.better-sol/auth.json`

Your API key for the cloud compiler. Created when you run `npx @better-sol/cli login`. This file is optional. Without it, you can still compile programs at a lower rate limit. See [Installation](/docs/getting-started/installation#api-key-optional) for details.

### `generated/counter/`

Generated when you run `deploy` (or `deploy --dry-run`). Contains the transpiled Anchor Rust project:

- `lib.rs` — the full Anchor program: `declare_id!`, `#[program]` module, `#[derive(Accounts)]` structs, `#[account]` structs, `#[error_code]` enum
- `Cargo.toml` — pinned to Anchor 1.0.x, includes `anchor-spl` only if token CPI is detected

This directory is for reference and for verified builds. You do not need to edit it. If you delete it, the next `deploy` regenerates it.

### `better-sol.config.ts`

Optional CLI configuration file. If it exists, the CLI reads it. If not, defaults are used.

```typescript
import { defineConfig } from "@better-sol/cli"

export default defineConfig({
  programs: "programs/**/*.ts",  // glob for program discovery
  cluster: "devnet",              // default cluster for deploy
  out: "generated",               // generated Rust output directory
})
```

### `keypair.json`

Your payer keypair. This is the wallet that pays for transactions (deployments, instruction calls). It is not generated by the CLI. You create it separately with `solana-keygen new`.

## The flow

```
programs/counter.ts
        │
        ├── transpiler ──→ generated/counter/lib.rs + Cargo.toml
        │                         │
        │                    cloud compiler ──→ counter.so (bytecode)
        │                                          │
        │                                    solana program deploy
        │
        └── betterSol({ programs: { counter } })
                        │
                        └── typed client (sol.counter.initialize, sol.counter.accounts.Counter.fetch, etc.)
```

The same file feeds both the transpiler and the client. There is no intermediate IDL, no code generation step, and no sync drift.

## Typical `.gitignore`

```
node_modules
.better-sol/
generated/
keypair.json
```

Keep `programs/` and `better-sol.config.ts` in version control. Everything else is either sensitive (keypairs, auth) or derived (generated Rust).
