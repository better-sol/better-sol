# Pitch, Grant, and Hackathon Assets

## Pitch deck

1. Title and one-line promise
2. Problem
3. Why now
4. Solution
5. Product demo
6. Why Solana
7. Technical architecture
8. Market/user segment
9. Validation or traction
10. Competition and wedge
11. Roadmap
12. Ask

## Hackathon submission

Required fields usually include:

- project name
- tagline
- short description
- long description
- track/category
- technical explanation
- what is on-chain
- deployed URL
- repository
- demo video
- devnet/mainnet addresses
- setup instructions
- team

## Demo script

```markdown
0:00 Hook: [pain]
0:15 Product: [what it does]
0:35 Live flow: [core action]
1:20 On-chain proof: [transaction/account/program]
1:45 Technical edge: [architecture]
2:10 Impact: [why it matters]
2:30 Close: [CTA]
```

## Grant draft structure

- project summary
- ecosystem benefit
- current progress
- deliverables
- milestones
- budget
- timeline
- risks
- proof links

## Better Sol proof points

Use when true:

- TypeScript program definition exists
- typed client uses same definition
- LiteSVM tests pass
- devnet/mainnet program address exists
- demo includes an on-chain state transition
- SDK reduced client-maintenance overhead
