# Grant Application

Use this reference when the user applies for a Solana, Superteam, ecosystem, hackathon, or developer tooling grant.

## Reviewer mindset

Grant reviewers want to know:

- What will exist after the grant?
- Why does the ecosystem need it?
- Why is this team likely to deliver?
- How will progress be verified?
- Is the requested budget proportional?
- What risks could block completion?

## Required facts to collect

- Grant program name and link.
- Deadline.
- Eligibility constraints.
- Project name and one-line summary.
- Current repo/demo/deployment links.
- Team members and relevant experience.
- What is already built.
- Requested amount.
- Milestones and dates.
- Deliverables per milestone.
- Maintenance plan after grant.

## Strong Better Sol grant angles

Use only when true:

- Lowers Solana onboarding friction for TypeScript developers.
- Produces reusable Better Sol examples or templates.
- Demonstrates typed Solana program/client development.
- Adds tests, docs, or tooling that other developers can reuse.
- Integrates with existing Solana protocols in a safer or clearer way.

## Milestone quality bar

Each milestone should include:

- concrete deliverable
- acceptance criteria
- verification method
- estimated completion date
- dependency or risk

Weak: “Improve UX.”

Strong: “Ship wallet transaction preview for deposit/withdraw flows with devnet smoke tests and screenshots in the README.”

## Budget guidance

Tie budget to outputs:

- engineering time
- design time
- audits/review
- infrastructure/RPC/indexer costs
- documentation/tutorials
- demo/video production

Avoid vague budget categories such as “operations” unless explained.

## Evidence checklist

- repository link
- live demo
- screenshots
- devnet/mainnet program address
- transaction signatures
- tests passing
- README setup
- user validation
- prior shipped work

## Common weak answers

- “We will onboard the next billion users” without a specific user.
- No measurable deliverables.
- No maintenance plan.
- No proof the team can build it.
- Mainnet promises without security plan.
- Grant asks for discovery work only, with no concrete output.

## Review before submission

Check that every answer is specific, verifiable, and free of hype. If a claim cannot be proven, either add evidence or soften the claim.
